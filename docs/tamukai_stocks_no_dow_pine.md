2. Pineエディタで新規ストラテジーを作成し、このファイル全文を貼り付け、チャートへ追加する。既存スクリプトは上書きしない。

## 凍結仕様対応

| 項目 | Python / Pineの条件 |
|---|---|
| 原本 | `scripts/research_tamukai_stocks_jev.py::candidate_signals(..., "no_dow")`、約定は `research_tamukai_stocks_daily.py::simulate` |
| 上昇判定 | 確定終値 > SMA21 > 2本前のSMA21 |
| 押し目 | 信号足を除く直前3本のどれかで、その足の安値 <= その足のSMA21 |
| 回復 | 確定終値 > 信号足を除く直前3本の最高高値 |
| エントリー | 無保有時に成行注文、原則として次の営業日の始値で買い |
| SL | 信号確定時の直前3本の最安値で固定。信号足安値を含めない |
| TP | 実約定価格 + (実約定価格 − 固定SL)。RR1:1で全決済、部分利確なし |
| 保有 | 買いのみ、同時1建玉。追加購入・売り・トレーリングなし |
| 除外した条件 | 高安切上げ（Dow）・ATR・SL幅2–4%フィルターなし |
| 確定と未来参照 | `barstate.isconfirmed`に加え約定再計算を除外。`request.security`、lookahead、未来オフセットなし |

約定再計算では固定SLと実約定価格だけを使い、当日の完成OHLCを新しい売買信号に使わない。通常の終値実行がある場合、決済した日の終値から次の営業日向けシグナルを作れる。約定と終値実行の重なる境界の動作はTradingView上で要照合。

## Pythonと一致しない可能性がある箇所

- **始値 <= SL**: Pythonは買わない。TradingViewでは前日に出した成行が既に約定するため、直ちに全決済して `INVALID GAP` と表示・件数集計する。往復費用が発生し得る。後から取引を消して一致させない。
- **同じ足でTPとSLの両方に到達**: Pythonは寄付きgapを先に処理し、その後SL優先。TradingViewは推定バー内経路で順序を決める。Bar Magnifierを有効にすると下位足配信に依存する別結果になり、Pythonの保守的なSL優先とは同じでない。
- **資金・数量**: Pythonは当日始値で `cash / (open * 1.001)` の調整後端株。TradingViewの数量算出・最小取引単位・残余資金・証拠金チェックは銘柄仕様に依存し、100株単位の実取引再現でもない。資金不足では注文不成立もあり得る。費用率を変更する場合、注文比率も `100 / (1 + 費用率)` に合わせ直す必要がある。
- **価格・費用**: RR1価格は明示的に丸めず計算し、表示はチャート最小刻み。実際の約定値は呼値やエミュレータ処理の差があり得る。片道0.1%は研究用費用仮定であり、実測スプレッドではない。スプレッド別加算・実滑り・税・配当・金利は入れていない。
- **最終日**: Pythonは期間最後の終値で強制決済する。Pineは保有を継続し未実現損益を分離するため、期間末の取引・純損益は一致しない。
- **配信・営業日・時刻**: Pythonは保存済みYahoo調整後日足、TradingViewはチャート提供元・調整設定・取引所セッションの日足。表示タイムゾーンだけでOHLCは一致しない。比較は営業日をJSTで照合し、欠損・休日・分割・配当調整の差も確認する。
- **元データ制約**: `data/stocks/yahoo/jp_largecap10_20260926/` を再利用する研究。Sonyの2025年調整未解明、8306/8035の2022-05-17高安修復、現在の大型株固定による選択バイアスを引き継ぐ。Pineは保存CSVを読み込まず、TradingViewから配信される足を使う。

Entry/TP/SLを名称と価格で表示し、決済後も線を残す。履歴線・ラベルは通常の確定終値処理で作成するため、リアルタイム決済直後は次の通常終値実行まで遅れる場合がある。同日決済の水平線は視認性のため1本先まで描くが、保有期間の延長ではない。TradingViewの最大500個制限により古い線・ラベルは順次消える（目安約165取引）。
