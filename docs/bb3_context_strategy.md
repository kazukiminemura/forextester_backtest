# BB ±3σ 文脈フィルター・PF検証版

`scripts/tradingview/bb3_context_strategy.pine` をTradingViewのPineエディタへ貼り付け、保存してチャートへ追加してください。検証したいFX通貨ペアの通常ローソク足・5分足を使用します。元の候補表示インジケーターは変更していません。

## 複数通貨ペアへの対応

PF検証版はUSDJPY限定を撤廃しました。EURJPY・GBPJPY・EURUSD・GBPUSDなど、表示中の通貨ペアで計算します。複数ペアの同時集計ではありません。5分足の制限は維持し、設定から解除できます。

- 自動pip幅は決済通貨がJPYなら0.01、それ以外のFXなら0.0001です。特殊な通貨・配信元でこの慣例と異なる場合は自動設定をOFFにし、手動入力してください。
- 節目幅は既定50 pips。円ペアでは0.5円、EURUSDなどでは0.0050となり、最小ティック単位に丸めます。USDJPYの従来の幅は維持しています。
- FX以外と判定された銘柄は、自動設定中は売買を停止して警告します。検証する場合は手動pip幅・注文数量・必要資金を銘柄仕様に合わせて設定してください。
- 右上に銘柄名と使用中のpip幅・節目幅を表示します。銘柄変更時は手動登録の経済指標も対象通貨に合わせて更新してください。
- 注文数量と口座通貨JPYは従来の設定を維持しています。同じ数量でも通貨ペアにより金額リスクが異なります。手数料・スプレッド相当コストもペア別に確認してください。

銘柄判定には[TradingViewの銘柄情報](https://www.tradingview.com/pine-script-docs/concepts/chart-information/)を使用しています。他通貨ペアへの対応は収益性の検証完了を意味しません。

## 検証用の売買仮定

- ±3σタッチは準備のみ。既存の高安・節目突破フィルター、手動指標除外を維持します。
- 準備足より後に候補が確定したら成行注文を作成し、原則として次足始値でエントリーします。これは裁量候補を機械的に売買するための追加仮定です。
- BB中央線に全決済の指値を置きます。中央線の注文価格は確定足ごとに更新し、次の利用可能なティック以降に有効です。同じ足の終値から計算した中央線で、その足の過去の高安に遡って決済しません。
- エントリー注文と同時に決済注文も提出します。保有中の追加エントリー・反転はしません。決済した足では新たな準備をしません。
- 固定損切りは任意です。原条件に損切り幅の指定がないため既定OFF、有効時の初期値は10 pipsです。約定価格から指定幅のティック数で設定します。USDJPYの1 pipは既定0.01円です。
- 中央線が動くことや窓開けにより、中央線決済でも利益になるとは限りません。RR固定の戦略ではありません。

## PFとコスト

右上にPF、決済数、勝率、純損益、含み損益を表示します。PFはTradingViewの集計値である `strategy.grossprofit / abs(strategy.grossloss)` です。決済なし・総損失ゼロでは数値を表示しません。勝率は利益となった決済数÷全決済数で、建値を勝ちに含めません。

**含み損益はPFに入りません。** 特に損切りなしの場合、未決済の大きな含み損を残したPFだけで評価しないでください。履歴末尾での強制決済は行いません。

設定の「プロパティ」で手数料・スリッページ・注文数量を確認してください。既定は口座通貨JPY、初期資金100万円、固定数量1000（ロットではなくTradingViewの銘柄単位）、手数料0%、スリッページ1ティックです。1ティックは1 pipとは限りません。スリッページはTradingViewの成行・逆指値注文の扱いに従い、指値に一律のスプレッドを課すものではありません。**既定値は実際のFX取引コストを再現していません。** Forex Testerとのコスト条件も一致していません。

計算対象はTradingViewが読み込んだ履歴です。3年分が自動的に取得されるわけではありません。ストラテジーテスターの対象期間、銘柄、コスト、注文数、未決済損益を合わせて確認してください。

## 制約・確認状況

- 「理由の説明がつかない動き」という人間の判断は再現していません。WEMOF原典を認証した実装でもありません。
- 指標時間は手動3件のみです。過去3年間の経済指標が自動除外されるわけではありません。
- バンド内への終値回帰条件は追加の補助仮定で、設定で無効化できます。
- 約定後再計算・毎ティック計算・終値約定は既定OFFです。設定を変更すると結果が変わります。通常足のOHLCによる約定推定には足内順序の限界があります。
- ローカルの構造テストのみ実施。TradingViewでのコンパイル・実行・PFの一致は未確認（TV_UNVERIFIED）です。実績PFや収益性を主張するものではありません。

注文の約定タイミングとコスト設定は[TradingView公式ストラテジー資料](https://www.tradingview.com/pine-script-docs/concepts/strategies/)を参照してください。
