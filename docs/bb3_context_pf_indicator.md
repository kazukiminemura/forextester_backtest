# BB ±3σ PFインジケーター

左下の通貨一覧には各通貨の「勝率」「決済数」を表示します。勝率は往復コスト控除後の損益が正の決済数 ÷ 全決済数で、未決済取引と予定エントリーは数えません。決済0件は勝率「—」、決済数「0」、対象外・データなしは両方「—」です。各通貨の読込済み履歴に依存し、全通貨に同じコスト設定を使用します。更新待ちの行では確認足時刻までの過去集計を表示します。将来のエントリー成功確率ではありません。メイン銘柄のPFパネルは既定で非表示のままです。

`scripts/tradingview/bb3_context_pf_indicator.pine` をPineエディタに貼り付け、チャートに追加します。以前のストラテジー版をチャートから外すと表示の重複を防げます。元のファイルは残しています。

USDJPY以外のFXにも対応し、既定は5分足です。JPY決済通貨は1 pip＝0.01、その他のFXは0.0001を自動設定します。特殊な銘柄やFX以外では自動をOFFにして価格幅を手動指定してください。節目幅は50 pipsが既定です。

## 表示と使い方

### 通貨別チャンス一覧

スキャナーで複数通貨の状態をまとめて確認できます。対象は設定欄で選んだ11銘柄で、市場の全通貨を自動検索するものではありません。既定はOANDAのUSDJPY・EURUSD・GBPUSD・AUDUSD・NZDUSD・USDCAD・USDCHF・EURJPY・GBPJPY・AUDJPY・NZDJPYです。利用中のチャートと同じデータ提供元に変更すると比較しやすくなります。

「チャンス通貨一覧（参考・未検証）」で表示ON/OFFと左上／左下の配置を選べます。既定は左下です。既存のチャートに左上の設定が残る場合は「一覧の位置」を「左下」に変更してください。同じ銘柄IDを複数枠に指定した場合は1行にまとめ、空の銘柄指定は表示中チャートの銘柄として扱います。無効な銘柄は「データなし」と表示します。

| 状態 | 読み方 |
|---|---|
| BUY信号／SELL信号 | 直前確定足で候補成立。緑／赤背景で最上位に表示 |
| 買い準備／売り準備 | バンドタッチ後の監視中。黄色文字で信号の次に表示 |
| 仮想BUY保有／仮想SELL保有 | 当該通貨の独自計算で保有中。新規信号ではない |
| 見送り／待機 | 条件除外／現在準備なし。見送り理由は状態セルのツールチップ |
| 対象外/計算待ち／データなし | 時間足・銘柄条件外、履歴不足、または取得不可 |
| 更新待ち（古い） | 確認時刻が現在より2本分超古い、または未来。通知しない |

準備と信号を区別し、信号がある通貨を優先表示します。「準備」は監視段階であり、エントリー指示ではありません。中央線までの距離は確定足の終値基準・コスト控除前で、実際の約定価格とは異なります。既存の最低3 pips・突破除外・長ヒゲ除外などの入力条件を引き継ぎます。

一覧はチャートと同じ時間足を使います。既定の5分足制限を有効にしたまま他の時間足にすると、信号は出しません。メイン銘柄のPF集計パネルは既定で非表示です。必要な場合だけ「表示」→「メイン銘柄のPF集計を表示」をONにすると右上へ表示します。表示中のチャート銘柄だけの集計で、一覧の通貨の合算PFではありません。表示の切替で売買条件やPFの計算方法は変更しません。

未確定足の点滅する信号をチャンスと扱わないよう、各通貨の1本前の確定結果を取得します。新しい足が始まり、表示チャートに更新が届いた時点で一覧へ反映されます。現在足の終了間際にはチャートの信号と一覧の表示が一時的に異なる場合があります。市場休場・配信停止などで古くなった結果はチャンス扱いにしません。ただし表示チャート自体に更新がなければ一覧や経過時間も更新されません。

取得にはTradingViewの[他銘柄データ取得仕様](https://www.tradingview.com/pine-script-docs/concepts/other-timeframes-and-data/)に沿った確定値取得を使います。`request.security()`内では[barstate.isconfirmedを使わない](https://www.tradingview.com/pine-script-docs/concepts/bar-states/)設計です。データの開始位置・提供元が異なると、仮想保有状態や信号も一致しない場合があります。

比較は通常ローソク足・同一配信元・同一時間足で行ってください。平均足などの合成価格チャートでは、表示チャートの価格とスキャナーの通常OHLCが異なります。リプレイ中の過去足は現在時刻から見て古いため、チャンス通知対象外です。

通知するには「一覧の確定BUY/SELL信号を通知」をONにし、TradingViewのアラート作成でこのインジケーターの「Any alert() function call（alert()関数の呼び出し）」を選びます。通貨名・BUY/SELL・中央線幅・確認時刻JSTをまとめて通知します。各銘柄の初回有効リアルタイム取得は初期化だけに使うため、装着直後に既に表示されていた信号は通知しません。同じ確定足の再通知を抑止します。設定やコードを変更した場合はアラートを作り直してください。実注文は発注しません。

### 表示チャートの信号・PF

「Entry・利確・損切りの価格ラインを表示」は既定ONです。チャート右端に青のEntry、緑の利確・中央線、赤の損切りの水平ラインと価格ラベルを表示します。通貨一覧ではなく表示中のチャート銘柄の仮想売買が対象です。

信号確定時は「BUY/SELL・予定・信号終値基準」と明示し、信号終値を参考Entry、候補確定時の中央線を決済目安として表示します。これは約定価格ではありません。次足が始まったら「仮表示・次足始値」としてその始値へ更新し、その足の確定後に仮想保有が残る場合だけ「仮想保有中」へ変わります。予定段階のSLも参考Entry基準のため約定価格確定まで変わり得ます。描画だけの先行表示で、未確定足の売買・PF集計は変更しません。

決済後は右端の3本のガイドを消し、過去の決済済み価格が新しい信号に重ならないようにします。過去の価格推移・決済ラベルは従来の履歴表示を維持します。保有中の中央線は次足用に更新されるため、Entryより損失側へ移動することがあります。その場合は緑の利確表示ではなく、橙色の「中央線決済・利益側ではない」と表示します。BUYなら必ずEntryより上へ線を押し上げる、といった実際の決済ルールと異なる描画はしません。

損切りラインは「固定損切りを使う」がONのときだけ表示します。OFFでは赤線はありません。SLを表示するために売買ルールやPF計算を勝手に変えることはしません。価格ガイドのローカル構造検査は実施していますが、TradingView上での表示は未確認です。

- 黄色の準備：BB20・±3σにタッチ。即エントリーではありません。
- BUY/SELL信号：準備後、高安・節目突破の勢いなどの除外を通過した候補。バンド内への終値回帰条件は設定可能です。
- 仮想BUY/SELL：候補の次の利用可能な足の始値。価格、当初の中央線決済価格、任意SLをラベル表示します。
- 中央線決済/SL：仮想決済の価格とコスト控除後pips。
- 右上のPF集計：既定では非表示。設定でONにした場合だけ、PF、決済数、勝率、確定損益、含み損益、コスト、pip幅を表示。

アラートは「買い候補確定」「売り候補確定」「仮想決済確定」です。足確定時の通知であり、実注文は出しません。仮想約定ラベルも当該足が確定してから表示されます。未確定足の仮想売買はまだ集計しません。

## 仮想売買の約定・集計仕様

### 長いヒゲの見送り

上側バンドにタッチした足の長い上ヒゲは売り準備を、下側バンドにタッチした足の長い下ヒゲは買い準備を見送ります。既に同方向の準備中でも、そのパターンで再タッチした場合は準備を解除します。保有中の強制決済や、バンドに触れない足の除外には使いません。

既定条件は「該当ヒゲが実体の2倍以上」かつ「高値−安値の50％以上」です。画像の特徴を数値化した仮定で、倍率・割合は設定で変更でき、フィルター自体もOFFにできます。実体がゼロに近い足は実体を最低1ティックとして判定し、高値＝安値の足は除外対象にしません。見送った足には「長いヒゲ」と表示します（他の見送り理由と重なる場合は既存理由を優先）。

### 中央線までの最低幅

候補確定足の終値から、その確定足のBB中央線までの利益方向の距離が3 pips未満なら、準備を解除して見送ります。買いは「中央線−終値」、売りは「終値−中央線」で判定し、3 pipsちょうどは許可します。入力で最低幅を変更でき、0で距離制限を解除できます（中央線到達済みの除外は維持）。不足時は「中央線までの幅不足」と表示し、BUY/SELL信号・予約・アラートを発生させません。

これはコスト控除前の距離です。次足始値での約定価格や、その後に動く中央線まで3 pips残ることを保証する条件ではありません。買い・売りとも銘柄別のpip幅を使い、価格計算の浮動小数点誤差だけを1e-9 pipsの許容差で吸収します。3 pips設定の収益性は未検証です。以前の5 pips設定の検証結果とは区別してください。

### 約定と損益の計算

これは `indicator()` 内の独自計算です。ストラテジーテスターや実口座の成績ではありません。

1. 確定した候補を予約し、次の利用可能な足の始値を仮想エントリー価格にします。週末などの欠損をまたいだ予約も次の利用可能な始値を使います。
2. エントリー足には候補確定時の中央線を使います。保有継続時は、その足の決済判定を終えてから中央線を更新し、次足に適用します。現在足の終値で算出した中央線を同じ足の過去の値動きに適用しません。
3. 窓開けで中央線やSLを超えた場合は始値決済。窓開けがない足で両方に触れた場合はSL優先です。足内の詳細な順序は再現しません。
4. 固定SLは既定OFF。有効時はエントリーのチャート価格から指定pipsを最小ティックに丸めた幅で設定します。追加保有、反転、決済足での新しい準備はしません。
5. 各決済の損益＝方向×（決済価格−エントリー価格）÷pip幅−往復コスト。往復コスト＝スプレッド相当＋片道スリッページ相当×2＋往復手数料相当です。価格ラベルと到達判定はコスト控除前のチャート価格です。Bid/Askの別系列は再現しません。
6. 既定コストは1.2＋0.1×2＋0＝1.4 pipsの例示値です。全決済に同じコストを課し、通貨ペアや時間帯に応じた自動更新はありません。設定で調整してください。ストラテジー版のコスト設定は引き継がれません。
7. コスト控除後で利益の取引だけを総利益に、損失の絶対値を総損失に加算し、PF＝総利益÷総損失とします。総損失ゼロの場合は数値PFを表示しません。勝率は利益取引数÷全決済数。建値は勝ちに含めません。
8. 等数量・pipsベースの集計です。口座通貨換算、複利、証拠金、資金不足、スワップは再現しません。各通貨ペア単独の結果で、複数ペア合算ではありません。

含み損益は現在の終値で全決済すると仮定し、往復コストを引いた参考値です。PFには含めません。履歴末尾の強制決済もありません。**特にSLなしでは、大きな含み損を残したPFだけで良否を判断しないでください。**

## 限界・検証状況

経済指標の日時入力・発表前後の除外判定・背景表示は削除しました。発表時間でも他の条件を満たせば信号と仮想売買が発生し、PF集計に含まれます。一般的な「裁量見送り：候補を全停止」は残していますが、履歴全体に適用するスイッチであり、個別日時を除外する機能ではありません。

「説明のつかない動き」という裁量は再現しません。WEMOFの公式仕様を認証したものではありません。通常ローソク足を使用してください。対象はチャートの読込済み履歴で、3年の履歴を自動取得するものではありません。

ストラテジー版とはコスト、足内順序、数量・資金制約、口座通貨換算の扱いが異なり、PFの一致は保証しません。

ローカルの構造チェックと仮想約定仕様の参照計算テストのみ実施。TradingView上のコンパイル・表示・計算は未確認（TV_UNVERIFIED）です。Pineの足ごとの実行と状態保存については[公式実行モデル資料](https://www.tradingview.com/pine-script-docs/language/execution-model/)を参照してください。
