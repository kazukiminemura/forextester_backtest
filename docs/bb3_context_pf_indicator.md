# BB ±3σ PFインジケーター

`scripts/tradingview/bb3_context_pf_indicator.pine` をPineエディタに貼り付け、チャートに追加します。以前のストラテジー版をチャートから外すと表示の重複を防げます。元のファイルは残しています。

USDJPY以外のFXにも対応し、既定は5分足です。JPY決済通貨は1 pip＝0.01、その他のFXは0.0001を自動設定します。特殊な銘柄やFX以外では自動をOFFにして価格幅を手動指定してください。節目幅は50 pipsが既定です。

## 表示と使い方

- 黄色の準備：BB20・±3σにタッチ。即エントリーではありません。
- BUY/SELL信号：準備後、高安・節目突破の勢いなどの除外を通過した候補。バンド内への終値回帰条件は設定可能です。
- 仮想BUY/SELL：候補の次の利用可能な足の始値。価格、当初の中央線決済価格、任意SLをラベル表示します。
- 中央線決済/SL：仮想決済の価格とコスト控除後pips。
- 右上：PF、決済数、勝率、確定損益、含み損益、コスト、pip幅。

アラートは「買い候補確定」「売り候補確定」「仮想決済確定」です。足確定時の通知であり、実注文は出しません。仮想約定ラベルも当該足が確定してから表示されます。未確定足の仮想売買はまだ集計しません。

## 仮想売買の約定・集計仕様

### 長いヒゲの見送り

上側バンドにタッチした足の長い上ヒゲは売り準備を、下側バンドにタッチした足の長い下ヒゲは買い準備を見送ります。既に同方向の準備中でも、そのパターンで再タッチした場合は準備を解除します。保有中の強制決済や、バンドに触れない足の除外には使いません。

既定条件は「該当ヒゲが実体の2倍以上」かつ「高値−安値の50％以上」です。画像の特徴を数値化した仮定で、倍率・割合は設定で変更でき、フィルター自体もOFFにできます。実体がゼロに近い足は実体を最低1ティックとして判定し、高値＝安値の足は除外対象にしません。見送った足には「長いヒゲ」と表示します（他の見送り理由と重なる場合は既存理由を優先）。

### 約定と損益

これは `indicator()` 内の独自計算です。ストラテジーテスターや実口座の成績ではありません。

1. 確定した候補を予約し、次の利用可能な足の始値を仮想エントリー価格にします。週末などの欠損をまたいだ予約も次の利用可能な始値を使います。
2. エントリー足には候補確定時の中央線を使います。保有継続時は、その足の決済判定を終えてから中央線を更新し、次足に適用します。現在足の終値で算出した中央線を同じ足の過去の値動きに適用しません。
3. 窓開けで中央線やSLを超えた場合は始値決済。窓開けがない足で両方に触れた場合はSL優先です。足内の詳細な順序は再現しません。
4. 固定SLは既定OFF。有効時はエントリーのチャート価格から指定pipsを最小ティックに丸めた幅で設定します。追加保有、反転、決済足での新しい準備はしません。
5. 各決済の損益＝方向×（決済価格−エントリー価格）÷pip幅−往復コスト。往復コスト＝スプレッド相当＋片道スリッページ相当×2＋往復手数料相当です。価格ラベルと到達判定はコスト控除前のチャート価格です。Bid/Askの別系列は再現しません。
6. 既定コストは1.2＋0.1×2＋0＝1.4 pipsの例示値です。全決済に同じコストを課し、通貨ペアや時間帯に応じた自動更新はありません。設定で調整してください。ストラテジー版のコスト設定は引き継がれません。
7. コスト控除後で利益の取引だけを総利益に、損失の絶対値を総損失に加算し、PF＝総利益÷総損失とします。総損失ゼロの場合は数値PFを表示しません。勝率は利益取引数÷全決済数。建値は勝ちに含めません。
8. 等数量・pipsベースの集計です。口座通貨換算、複利、証拠金、資金不足、スワップは再現しません。各通貨ペア単独の結果で、複数ペア合算ではありません。

含み損益は現在の終値で全決済すると仮定し、往復コストを引いた参考値です。PFには含めません。履歴末尾の強制決済もありません。**特にSLなしでは、大きな含み損を残したPFだけで良否を判断しないでください。**

## 限界・検証状況

経済指標の日時入力・発表前後の除外判定・背景表示は削除しました。発表時間でも他の条件を満たせば信号と仮想売買が発生し、PF集計に含まれます。一般的な「裁量見送り：候補を全停止」は残していますが、履歴全体に適用するスイッチであり、個別日時を除外する機能ではありません。

「説明のつかない動き」という裁量は再現しません。WEMOFの公式仕様を認証したものではありません。通常ローソク足を使用してください。対象はチャートの読込済み履歴で、3年の履歴を自動取得するものではありません。

ストラテジー版とはコスト、足内順序、数量・資金制約、口座通貨換算の扱いが異なり、PFの一致は保証しません。

ローカルの構造チェックと仮想約定仕様の参照計算テストのみ実施。TradingView上のコンパイル・表示・計算は未確認（TV_UNVERIFIED）です。Pineの足ごとの実行と状態保存については[公式実行モデル資料](https://www.tradingview.com/pine-script-docs/language/execution-model/)を参照してください。

## 行数削減レビュー

経済指標コード削除後の251行を見直し、221行へ短縮しました（空行・コメントを含む、30行削減）。入力項目・既定値、約定関数、pips計算関数は変更前と一致しています。単なる改行の圧縮や複数命令の1行詰め込みはしていません。

| 対象 | 必要性と整理内容 |
|---|---|
| 入力・価格単位 | 利用者の調整項目なので維持。pip幅、最小ティックへの丸めも必要 |
| 突破履歴 | 上下の高安・節目の4履歴は別々に必要。関数呼び出しを条件式の短絡評価内へ移すと更新を飛ばすため、4呼び出しを維持 |
| 欠損足判定 | 同じ判定を2か所で繰り返していたため共通化 |
| エントリー予約 | 確定足で信号を出し、次の利用可能な始値で約定させるため必要。予約方向・足番号・中央線価格を維持 |
| 保有・決済 | 当該足の旧中央線で決済判定してから更新する順序を維持。表示用の価格保存も当該足・決済足の履歴表示に必要 |
| enteredフラグ | エントリー後は「保有中」か「同足決済済み」のどちらかで既に新規準備を抑止できるため削除 |
| 準備・信号フラグ | 買い/売りの相互排他的なboolをそれぞれ方向値（0、1、−1）に統合 |
| 見送り・処理済みフラグ | 見送り理由と信号方向から判定できるため削除。準備解除の共通処理へ統合 |
| 損益集計 | 正負の分岐をmath.maxで整理。勝ちはコスト控除後で正の取引だけ、建値は勝ちに含めない |
| PFのゼロ除算対策 | 決済なし・総損失ゼロを区別するため維持。含み損益もPFから分離したまま |
| 描画・アラート | 履歴価格・サイン・3種類の通知を維持。表の2セル描画をtableRow関数へ共通化 |
| コメント・空行 | 重複説明のみ整理し、約定順序・独立状態などの重要な理由は残す |

変更前後の準備状態遷移をPython参照モデルで24,576条件比較し一致、関連テスト26件合格。これはPineコード自体を実行した比較ではなく、TradingViewでの同一結果を保証する検証ではありません。仮想エントリーラベルが当該足確定後に表示される仕様も変更していません。
