# YTT × Jev 5分監視アプリ

## 計画・必要性
手動撮影の繰り返しを省き、画像の買い/売り候補だけを知らせるユーザー依頼。既存の画像判定API・型検証・固定費用台帳を再利用し、既存画面にブラウザ標準の画面共有と通知を追加する。新しい戦略研究・自動注文・Codex定期タスクは作らない。

## 固定条件
1. ユーザーが共有対象として選んだブラウザのチャートタブ、またはチャートだけを表示したウィンドウを撮影する。デスクトップ全体は受け付けない。共有直後はプレビューだけ表示し、ユーザーが確認ボタンを押すまでAPIへ送らない。開始時に1回、その後300秒以上の間隔で撮影する。遅延分のまとめ送信はしない。
2. 1回の応答を待ってから次を予約する。停止・共有解除・ページ終了では未完了の応答も画面反映/通知に使わない。サーバー側でも同時推論と監視の300秒未満の再送を拒否する。
3. 前回と同じ銘柄/方向の候補の連続通知は抑制する。様子見を挟んだ候補、反対方向の候補は再通知する。通知許可がない環境でも画面に知らせる。様子見はトレード通知しない。
4. 古い画像・無効な応答・API障害・費用上限は様子見とし、エラーと費用切れで監視停止する。通知は有効なAPI応答の買い/売り候補だけ。AI確率は勝率ではない。
5. ユーザー回答により**今回の試験枠3円を維持**。既存予約0.5505024円も引き継ぎ、1回0.5505024円の事前予約なので追加4回まで。上限を増やさず失敗も消費し、自動再試行しない。残回数を画面に表示する。

## 使用方法
前提はPython 3.11以降とPillow（未導入なら `python -m pip install Pillow`）。WindowsではAPIキーを環境変数 `TYPESAFE_API_KEY` に設定する。キーをソースや画像へ含めない。

`scripts/start_ytt_jev_monitor.cmd` を開くか、`python scripts/ytt_jev_vision_app.py --open-browser` で起動する。Chrome/Edgeで http://127.0.0.1:8787/ を開き、同じブラウザでよすが式のTradingViewチャートを開く。

銘柄・時間足を合わせ、監視開始からチャートのタブまたはチャートだけを表示したウィンドウを共有し、プレビューを確認して「このチャートを監視」を押す。必要なら通知を許可する。PCとブラウザを起動したままにする。停止ボタン・共有停止・画面を閉じる操作で終了する。起動時やPC再起動時の自動開始はしない。

## 制約
ブラウザの共有選択と通知許可はユーザー操作が必要。停止前にAPIへ送信済みの1件は通信完了まで残る場合があり、その予約費用は戻らない。停止後の結果表示・通知は破棄する。ブラウザが最小化・省電力・バックグラウンド・PCスリープなどで制限されると正確な5分間隔は保証できない。API障害時の再試行は手動再開とし、費用消費を増やさない。

共有するタブ/ウィンドウを別ページや別銘柄へ変えない。口座・注文パネルは閉じる。共有範囲のURLや口座情報がないことをアプリが完全に保証することはできない。画像の日時・上位足・新規成立の識別はJevの確率的判断であり原価格との決定的照合ではない。前回のUSDJPY画面は必要な日時と上位足が十分見えず様子見だった。必要情報が見える表示で使用する。

## 引渡し時の状態
初回の自動判定後、共有元タブの終了を検知して停止したことを実画面で確認した。現在は共有終了による停止状態。再開時は共有対象を選び直す。無人の常時稼働は開始しておらず、試験枠を超えて判定しない。
