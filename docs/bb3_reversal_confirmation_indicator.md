# BB ±3σ 反転確認・突破待ちインジケーター

専用ファイル `scripts/tradingview/bb3_reversal_confirmation_indicator.pine` をTradingViewのPineエディターに全文貼り付け、チャートに追加します。既存PFインジケーターは保存したまま、表示だけOFFにすると旧信号との混同を避けられます。現在チャートのRR1仮想勝率を右下に表示します。既存の検証成績はこの新ルールの成績ではありません。

## BUY（SELLは上下・陽陰を反転）

1. −3σタッチで準備。タッチ足自身では反転確定しません。
2. 後続足が陽線で、終値が両バンドの内側にあると反転確認。その足の高値を突破基準として固定します。
3. さらに後の足で基準高値を厳密に上抜くと候補。同値タッチのみは不可。ヒゲで突破した後に終値が戻っても候補になります。表示・通知は足確定時です。
4. 準備時の安値を後続足が厳密に下回った場合は取消。反転確認前の安値更新も取消とし、安値を切り下げて待ち続けません。

準備中に安値更新があれば直ちに取り消すため、「準備後の最安値」は有効な準備中には準備足安値から変わりません。取消足での即再準備はしません。

同じ足で突破と安値更新の両方がある場合、5分足OHLCだけでは順番が分からないため取消を優先します。これは実際に突破が先だったケースも見送る保守的な表示です。

## 表示とタイミング

突破基準・取消水準を価格付きで示します。**取消水準はエントリー前の無効化条件であり、保有後の損切り注文ではありません。**
シグナルとアラートは突破足の確定時にのみ発生します。線の突破をリアルタイムで先回り通知したり、注文を発注したりするものではありません。
候補価格はBUYが「始値と突破基準+1tickの高い方」、SELLが「始値と突破基準−1tickの低い方」という参考値です。足確定時にその価格で約定できる意味ではありません。
参考価格から直前確定足のBB中央線まで最低3pips必要（設定可能）。終値からの幅や終値での突破維持は要求しません。コスト控除前であり、スプレッドや滑りは含みません。
最初の突破足が参考価格での最低幅を満たさない場合、その準備を取り消します。次の突破まで持ち越しません。

長いヒゲ・突破の勢い・節目等の見送り設定、5分足制限、pip自動設定を備えます。待機期限は追加仮定として準備後12本が既定で、変更可能です。実運用に適した期限と確認された値ではありません。

## 左下の通貨チャンス一覧

新しい反転確認ルールで各通貨を個別判定し、候補→突破待ち→反転足待ちの順で左下に並べます。各通貨の突破基準・準備取消水準・中央線幅・確認足時刻を表示します。従来BBの即時候補やPF表を流用したものではありません。

監視銘柄は設定から変更できます。既定は従来どおりUSDJPY/EURUSD/GBPUSD/AUDUSD/NZDUSD/USDCAD/USDCHF/EURJPY/GBPJPY/AUDJPY/NZDJPY。配信元はOANDAであり、GMOの実配信価格ではありません。USDCADはGMO FXネオの取扱対象外なので、GMOで取引する通貨だけを監視する場合は設定で置き換えてください。EURJPY/GBPJPY/USDCHFのForex Tester品質注意は過去検証側の問題であり、今回の一覧はTradingViewの配信データを参照します。

一覧は直前確定足の情報を次足の更新時に表示するため、現在チャートの確定マークより更新が遅れる場合があります。時刻はJST表示。現在チャートが更新されなければ一覧も更新されず、休場中もタイマーで動くものではありません。2本分を超えて古い情報や未来時刻は更新待ちとし、チャンスとして強調しません。

新手法の勝率・PFは未検証なので一覧には表示しません。既存アラートは現在チャートの候補だけが対象です。

一覧の候補行の中央線幅は「ギャップ調整した候補参考価格から前足中央線まで」です。突破待ち行は従来どおり「突破基準±1tickから確定中央線まで」の見込み幅です。どちらも現在価格での取引可否を保証しません。

## RR 1:1 の仮想勝率

- 対象は現在チャートの通貨・読み込まれた履歴のみ。11通貨一覧は従来の候補表示だけを維持し、集計負荷を増やしません。
- サイン確定の次足始値で仮想エントリー。利確はサイン確定時のBB中央線をtick単位に丸めて固定します。次足始値時点ではこれが直近確定中央線です。
- 損切り価格は `2 × エントリー価格 − 利確価格`。利確も損切りも全決済し、保有中の中央線移動には追従しません。RR1はコスト控除前の注文距離です。
- 次足で中央線が利益側にない・最低幅を満たさない・足の時間欠損がある場合、予約を破棄します。同時保有は1件。保有中の追加候補は集計しませんが、サイン・通知は変更しません。
- エントリー足でも決済します。同一足でTP/SL両方ならSL優先。保有中に窓を開けてTP/SLを越えた場合は始値決済なので、実現損益は厳密な±1Rとは限りません。
- 往復コストの仮設定は1pip（変更可能）。GMOの自動スプレッド取得ではなく、スワップも含みません。銘柄に合わせて設定してください。
- 勝率は「コスト控除後の損益が正の決済件数 ÷ 全決済件数」。損益ゼロは勝ちに含めません。未決済は分母から除外し、含み損益を別表示します。決済0件は「—」です。
- 集計・含み損益は確定足時点の更新です。仮想Entry/TP/SLは価格ラベルと履歴線で区別します。既存の「準備取消水準」はポジションのSLではありません。
- 勝ち判定では浮動小数点誤差による誤計上を防ぐため、1e-9pips以下の利益はゼロ相当として扱います。
- 過去の候補参考Entry価格ではなく次足始値を使うため、すべての表示サインが集計取引になるわけではありません。これはチャートOHLCの模擬集計であり、実約定・Forex Testerでの独立検証ではありません。

## 通知の設定

最新版をチャートへ反映した後、TradingViewで新しいアラートを作成します。
条件はこのインジケーターの「Any alert() function call（任意のalert()関数呼び出し）」を選択し、「アプリに通知」をONにしてください。
この1件でBUY・SELLの両方を受け取れます。片方向だけなら「BUYエントリー条件成立」または「SELLエントリー条件成立」を選び、頻度を「バーの終値ごとに1回」に設定します。
両方向まとめ通知と片方向通知を重複作成すると同じ成立を複数受信するので、どちらか一方の方式を使ってください。

通知は現在チャートの条件成立足の確定時のみ。準備・反転確認・取消では通知しません。他通貨一覧は通知対象外です。
まとめ通知には通貨・時間足・BUY/SELL・確定終値・足終了時刻（JST）を含みます。参考Entryで約定したことを示す通知ではありません。
スマホは同じアカウントでログインし、OS側でもアプリ通知を許可してください。
以前のアラートはコード更新を反映しないため削除して作り直します。スクリプトの変更だけではアラートは作成されません。
仕様参照: [TradingView公式アラート説明](https://www.tradingview.com/pine-script-docs/concepts/alerts/)。実際のスマホ着信は未確認です。
