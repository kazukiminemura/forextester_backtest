# YTT × Jev API 研究結果（2026-10-10）

Jev APIとの接続・過去データ評価は実装して実行した。現方式の収益改善は確認できず、TradingViewの売買条件には採用しない。状態は `NEEDS_EVIDENCE`。

## 実行と費用

- 累計1,887件送信、有効1,884件、無効3件。事前固定の「累計3無効で停止」により正常終了（exit 0）。追加API送信・リトライは行わない。
- 全6,659候補の28.29%が有効評価済み。各通貨628件。USDJPYのaccept分類196、EURUSD114、GBPUSD150（合計460）。これは実測勝ち数ではない。
- 有効応答の2,646,595 input tokensに対応する管理換算22.231398円＋無効3件の保守的予約1.6515072円＝23.8829052円。公式単価0.042 USD/百万input tokens、200円/USDで管理。100円上限内。実請求額・実為替の確定値ではない。
- 有効応答の平均時間0.192966秒、最大0.511465秒。過去データのAPI応答時間であり、TradingView通知から実取引までの遅延ではない。
- 無効3件はすべてChoice選択と表示確率の最大値が不一致。結果後に契約を緩和せず、元応答を保存した。

## 比較結果

2020–2022の部分評価。USDJPY/EURUSD/GBPUSD、15分足、確定日足・週足方向一致。AIなし対照もAI側も同じ1本待機・同じSL・同じ目標RR。同じ有効評価済み母候補を用い、AI側だけ固定閾値0.5の構造判断で選別した。トレード数が異なるため、勝率差や総損失の縮小だけを有効性の証拠にしない。

通常の仮定spread/slippageを控除した3通貨のR単位診断合算（円口座のポートフォリオではない）。

実現payoff＝費用後の平均利益÷平均損失絶対値。目標RRと異なり、時間決済・費用・ギャップなどを反映する。PF＝総利益÷総損失絶対値。1未満は費用後赤字。

Jev選別のPFは全3目標RRで1未満。RR1では勝率が45.75%→46.36%となったが、赤字のまま。RR1.5/2では実現payoffが同RR対照より低い。目標RRを引き上げるだけで利益改善したとは言えない。

費用2倍のJev選別でも全3目標RRが赤字（PF 0.646 / 0.649 / 0.657、合計 −44.459 / −48.826 / −49.547R）。GBPUSD単独RR2通常のみ+2.710R/PF1.069だが、同通貨費用2倍は−4.015R/PF0.907。部分的な黒字を採用根拠にしない。

## 判定と制約

1. 全候補の評価が未完了なので学習screenは判定不可。取得済み部分も合算黒字・PF1.2の条件を満たさない。検証期2023–2024と記述期2025へのAPI送信は実施しない。
2. 全期間は過去に閲覧済みで、未使用holdoutはない。独立期間・通貨の改善検証、候補当たり期待値差の月block信頼区間、API費用控除の口座検証は完了していない。
3. 仮定spread/slippage、source時計/価格side不明、swapなし、実bid/ask未再生、不完全バー露出を保存。資金100万円・10万円停止の実運用や月利5%を成立させた結果ではない。
4. AI判断は24本の確定OHLCなどの構造分類。未来値・損益・口座情報・銘柄名・日付は送信していない。AI確率をトレード勝率として表示しない。
5. Pineは任意外部HTTPを呼べないためPython研究bridgeでAPI連携した。TradingViewでの常時AI監視・通知受信・実注文連携は未実装。検証不合格/未完了のフィルターを既存Pineに入れない。
