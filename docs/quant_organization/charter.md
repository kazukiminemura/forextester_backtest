# クオンツAI組織 運営規約

目的は、このPCのForex Tester履歴から新しい売買ロジックを構築・独立検証し、
基準を満たしたロジックをTradingView用Pine Scriptとして引き渡すこと。
第一段階は組織構築。実口座への自動売買は今回の工程に含まない。

## 組織と編集責任

|担当|役割ID|主な成果物|判断権限|
|---|---|---|---|
|研究責任者（主エージェント）|quant_director|計画・実験台帳・統合報告|担当割当と工程移動|
|データ品質|quant_data|データ台帳・期間・品質問題|利用可能性の報告|
|クオンツ研究開発|quant_researcher|新規仮説・Python戦略・テスト|学習範囲内の設計|
|独立検証|quant_validator|再現結果・期間/通貨別判定|研究基準への適否|
|TradingView移植|quant_pine|Pine・導入手順・仕様対応表|凍結仕様の移植|
|品質監査|quant_auditor|証拠照合・不備・引渡し判定|不備による差戻し|

6つは担当の種類であり、常時6プロセスを動かす設定ではない。
主担当1+子担当最大3の枠で段階的に起動する。主担当が研究責任者を兼ねる。
6つのクオンツ役は各役割の設定により `gpt-6.1-sol` とhigh reasoningを使う。
Git公開担当だけは、ユーザー指定により `gpt-6.1-sol` とmedium reasoningを明示的に使う。
専用APIキーやモデル変更を新たに要求しない。
担当境界は指示による運用上の分離であり、OSレベルのアクセス制御ではない。
サブエージェントを増やしても独立したデータや統計的な独立性は増えない。

## 工程

1. DATA_READY: データ担当がローカル履歴の利用可能性と制約を報告。
2. SPEC_FROZEN: 開発担当が仮説・仕様を作成し、責任者が実験条件を記録。
3. IMPLEMENTED: 開発担当がPythonで実装し、境界条件のテストを実行。
4. VALIDATED / REJECTED: 独立検証担当が事前基準を適用。不採用は保存して終了。
5. PINE_CREATED: 合格仕様だけを移植担当へ渡す。変更があれば再検証。
6. TV_VERIFIED / TV_UNVERIFIED: 実際のTradingViewでコンパイル・表示・挙動を確認。
7. DELIVERED: 監査担当の所見を添えて責任者が結果と限界を引き渡す。

実行エラーは FAILED、情報不足は NEEDS_EVIDENCE とし、REJECTEDと区別する。
組織構築の完了は戦略のVALIDATEDやDELIVEREDを意味しない。
TV_UNVERIFIEDのファイルは確認待ちとして渡せるが、完成検証済みとは呼ばない。

## 実験前に固定すること

実験ごとに `docs/quant_organization/experiments/<id>/` を作成する。
`hypothesis.md`、`protocol.json`、`validation.md`、`audit.md` を証拠として保存する。
数値結果・取引一覧など大型成果物は `agent_runs/<id>/` に保存し、相対参照を文書に残す。
最初に `templates/protocol.json` を複製し、未定項目を埋める。nullのまま実験を始めない。

- なぜ期待値があるか、どこで反証されるか。単純な比較対象。
- 銘柄、時間足、確定足・上位足の使用、エントリー、全決済RR1:1。
- 元データの位置、期間、時刻基準、価格種別、識別子、欠損の扱い。
- 学習・検証・最終確認期間、過去の閲覧状況。真の未使用かは別に記録。
- 候補数・探索範囲・終了条件。採用が出るまで無制限に再探索しない。
- 取引数・コスト後PF・期待値・最大DDなどの数値基準と通貨横断の判定方法。
- スプレッド・手数料・スリッページ・スワップ・口座通貨/資金量・約定順序。

基準は新規研究前に責任者が根拠とともに決める。組織設立時点で収益を保証する閾値はない。
以前のagents.pyのPF1.2等を、別戦略の実運用基準として無条件に流用しない。
検証で落ちた戦略を改善するときは新しい実験IDを使い、既に見たデータを未使用扱いしない。
最終確認は学習・検証で選抜後に行い、成績を見て条件変更したら新しい未使用評価が必要。

## 引継ぎ

すべての担当は `templates/handoff.md` の形式で、入力識別子・出力場所・
実行コマンド/終了コード・検証済み事項・不確実性・次の担当を報告する。
数値は実ファイルを根拠とする。記憶や途中ログを現在の実行結果として記載しない。
責任者がboard.mdを更新し、依存工程の完了前に次の担当へ成果物を渡さない。
開発者と検証者を分け、検証者と監査者に戦略を都合よく書き換えさせない。

## 起動方法

このプロジェクトのCodexタスクで、たとえば次のように指示する。

> クオンツAI組織で研究を開始。研究責任者がデータ担当と開発担当へ委任し、
> ローカルForex Tester履歴を使う実験計画を固定してから新規戦略を実装・検証してください。
> 独立検証で合格したものだけTradingViewへ移植し、監査結果とともに報告してください。

設定は `.codex/agents/quant_*.toml`。対応Codexがプロジェクト設定を読込む際に検出する。
このPCのCLI 0.144.5では最新資料の `agents.enabled` が読込エラーとなるため、
`.codex/config.toml` の明示的な役割登録と `max_threads = 3` を使用する。
最新資料のフィールドをそのまま追加しない。ローカル互換性を優先する。
既存セッションへのホットリロードは確認していない。役割が見えない場合は新しいセッションで
このプロジェクトを開くか、AGENTS.mdに記載した担当指示を通常のサブエージェントへ渡す。
設定ファイルは担当の定義であり、自動スケジューラではない。無人常時運転は設定していない。
旧 `python -m forextester_backtest.agents` は条件比較器で、組織の起動コマンドではない。

設定方法: [OpenAI公式サブエージェント資料](https://learn.chatgpt.com/docs/agent-configuration/subagents)
