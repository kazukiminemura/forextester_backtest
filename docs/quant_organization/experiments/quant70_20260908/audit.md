## 残る制限と報告上の要件

1. `stats()` に `losses` / `breakevens` の明示フィールドがない。勝率の計算自体は正しく、建値は勝数に含まれない。実結果の取引JSONLから負・ゼロ損益数を独立集計し `independent_verification.json` に全候補・期間・通貨別で補足保存した。実行ハッシュを維持するため本監査で実装は変更していない。
2. RR1は発注時の距離であり、滑り・ギャップ・期間末強制決済後の実現損益は必ずしも±1Rにならない。`period_end` 件数と通常決済勝率を必ず併記し、強制決済を除外して70%到達としない。
3. `signal_time` / `exit_time` はバーの開始時刻。シグナルが知り得るのは当該15分足終値時点、期間末決済も当該足終値時点。OHLC内の正確な決済時刻は取得していないため、これらをティック精度の約定時刻と解釈しない。決済DDの同一時刻内順序は通貨名によるもので、ポートフォリオ時価DDではない。
4. スワップ、時変スプレッド、数量丸め、時価評価DD、相関、下位1分構成の完全性は未モデル化または未認証。同時保有は最大11通貨、予定損失合計は最大2.75%だがギャップにより超過する。実運用承認はできない。
5. Wilson下限は単純な二項独立仮定の参考値・事前選抜規則であり、相関取引や24候補探索を調整した70%の保証ではない。プロトコルは点推定70%以上を要求している。
6. 損失ゼロのPFは `None` として評価不能・不合格になる保守的な実装。損失ゼロをInfinityとして合格させる仕様ではない。候補数・PF・統計定義を成績閲覧後に緩めない。
7. 過去の研究で後半期間は閲覧済み。今回の候補選抜から隔離していても、真の未使用期間とは呼ばない。
