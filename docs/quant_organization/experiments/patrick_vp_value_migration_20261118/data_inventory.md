## データの制約

1. 保存時刻はタイムゾーンなし。既存再生のUTC・Bid仮定を用いる場合、JST08:00と08:15は保存前日の23:00と23:15になる。週末の再開時刻の変化とBars/ticksの一致状況から、全通貨・全年代の時計と価格種別を確定できない。EURHKDは保存ticksが0。M1の始終値とticksの始終Bidが一致しない時間帯もサンプル照合で確認した。

VPは保存M1のHLC平均価格に、有効な保存volumeを配分する既存近似。保存volumeの経済的意味は未確定。現行実装は負volume・非有限値を含む週などを無効とし、補間しない。通貨ごとのinfo.datは保存された取引設定であり、従来の比較ではJPYペア0.01、その他0.0001を1 pipとし、通常／厳しめの固定費用を再生する。[元の価格・費用・VP仕様](../patrick_h4_7d_winrate_20261107/data_inventory.md) / [プロファイル生成](../../../../scripts/backtest_patrick_vp_jst.py)

## 早朝データの利用可能性

保存時刻UTC仮定でJST火〜金の08:00と08:15がともに存在する16通貨の通貨日を数えた。直前225分のM1がすべてあるのは、2017〜2019年5,791/9,932、2020〜2022年2,824/9,672、2023〜2025年1,638/9,851、2026年1月6日〜8月27日54/2,119。JST月曜の直前225分連続は全期間で0だった。2026年追加の現行K10保存取引では、通常3/137件、厳しめ1/47件だけが225分連続。既存の反転計算に使う3区間の始終点6本は通常82/137件、厳しめ23/47件に実在した。これはデータ可用性の診断であり、反転候補の件数や収益の評価は含まない。[既存の反転検証](../patrick_cost10_m15_reversal/validation.md)

## 再現と引継ぎ

`PYTHONPATH=src` で `python -B -` に読取専用の照合を入力した。履歴端点は `HistoryRepository().summary(symbol)`、SHA256は `hashlib.file_digest` で計算した。M1の時刻は `rint(Bars.datのOLE時刻 × 1440)` で分単位にし、対象分の完全一致を `searchsorted` で確認した。決済台帳は[現行K10出力](../../../../agent_runs/patrick_cost10_va_preentry_shape/)の `<symbol>_<normal|stress>_small_pullback.npy` からentry時刻を読み、同じ時刻列から08:15の225分前〜1分前、および相対分 `[-225, -151, -150, -76, -75, -1]` の可用性を数えた。各コマンドは終了コード0。現物監査は端点・全保存時刻・ハッシュ・対象時間窓を確認し、価格とtickの比較はサンプルに限定した。

変更ファイルはこの台帳のみ。採用評価には時刻・価格・出来高の仮定を引き継ぎ、新しい期間の評価を別途要する。実注文なし。
